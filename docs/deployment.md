# Deployment

One image (`Dockerfile`) runs the Next.js app and the WhatsApp bot side by side
(`scripts/start.mjs`). `docker-compose.yml` adds Postgres and two volumes: `freitach-db`
for the database and `freitach-data` for `/data`, where the bot keeps its WhatsApp login.

## Coolify

1. New Resource → this repository → build pack **Docker Compose**
   (`docker-compose.yml`).
2. Environment Variables: set `ADMIN_NAME` and `ADMIN_PHONE` (required; on an empty
   database they create you as admin and default host, and the login link appears in the
   app's log). `APP_URL` defaults to `https://freitach.arns.dev`, the default restaurant to
   Pizzeria Rustica; the database user and password are generated by Coolify.
3. Domains: enter `https://freitach.arns.dev:3000` for the `app` service. The `:3000` only
   tells Coolify's proxy which container port to use; the site is served on 443.
4. Deploy. The app migrates the database on start; `GET /api/health` answers once it is up.
5. Open the login link from the log, or log in with your phone number once the bot is linked.

Nothing is published on a host port, so the app does not collide with other services on the
server (such as the one on 8080).

## Without Compose

The `Dockerfile` also runs on its own: give it `DATABASE_URL` (Postgres), `APP_URL`, a
volume at `/data` and the variables from `.env.example`. It listens on `PORT` (default
3000), which can also be set at build time (`--build-arg PORT=3500`). The bot's own port
(`BOT_PORT`, default 3001) is only used inside the container.

## Domain

`arns.dev` uses Cloudflare as DNS. Point `freitach.arns.dev` at the server (A/AAAA record)
and let Coolify route it to the app. `APP_URL` must match it: login links, the iCal feed and
the WhatsApp messages are built from it, and session cookies are only marked secure when it
starts with https.

## Linking WhatsApp

The bot is a linked device on a WhatsApp account, ideally a separate prepaid number. This is
not Meta's official API: it is free and works in groups, but WhatsApp can block numbers it
considers automated, so keep the volume to what the group needs.

Open the people page (Leute) as admin: it shows whether the bot is connected and, if not, a
QR code to scan in WhatsApp → Linked devices. With `PAIRING_PHONE` set to the bot's number
(digits with country code) it shows a pairing code instead, for WhatsApp → Linked devices →
Link with phone number. The same card lists the bot's groups; put a group's id into
`WHATSAPP_GROUP` for announcements there.

`WHATSAPP=off` runs the app without the bot; every message is then only written to the log.

## Lieferando menus

Lieferando blocks server-side requests, so menus come in through the browser: the bookmarklet
on a restaurant's page reads the open Lieferando menu and hands it to the import preview, and
plain copy and paste works too. Members can add a missing dish with its price on any Friday.

## Backups

Everything worth keeping is in Postgres, e.g.
`docker exec <db container> pg_dump -U <user> freitach > freitach.sql` (Coolify can also back
up the `freitach-db` volume). The WhatsApp login in `/data` can be recreated by linking again.
